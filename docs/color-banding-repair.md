# 周期性颜色横带修复

2026-11-24，分支 `feature/color-banding-repair`，B 负责。

## 适用范围

投影仪、LED 面板在卷帘快门下拍摄时，三个颜色通道的调制量不同，画面出现绿紫交替的横向色带，而整幅亮度几乎不变。现场照片（1600×1200 预览）检测报告为「颜色候选周期：391 像素行」。

亮度修复看不到这种横带：`BandingRepair` 只处理灰度，且在 64 px 周期以内。

## 与检测的分工

- A 的 `detectBanding` 给出周期和 `colorEvidence`（自相关 + 四区域一致性）
- B 的 `ChromaBandingRepair.repairWithPeriod()` 只做拟合，不做检测
- 周期不可靠时（解释不了实际调制）修复直接放弃，不会改动像素

`BandingPhotoProcessor` 的顺序是：颜色修复优先 → 摩尔纹拦截 → 亮度修复。颜色修复必须排在摩尔纹之前，因为投影幕布容易同时被判为疑似摩尔纹。

## 方法

三个通道分别按行取对数均值，得到 R、G、B 的对数轮廓。乘性频闪在对数域变成加性：

1. 用 `log(R/G)`、`log(B/G)` 判断色带，用亮度轮廓判断明暗横带
2. 周期在报告值附近 ±6% 内精修，取色度调制能量最大者
3. 每个通道在基频上最小二乘拟合，增益 `exp(-拟合值)` 并夹在 0.5..2.0
4. 施加时按 `strength` 与原图混合，原数组不变异

**只用基频，不拟合谐波。** 391 px 的三次谐波约 130 px，正好是投影幕布文字行的尺度；拟合谐波会把文字当成横纹谐波，沿整幅图留下约 10% 的细条纹。投影的色带本身接近正弦，谐波收益很小。周期 ≤ 128 px 时仍保留谐波，那里的 PWM 波形可能确实非正弦。

## 门限（均为实测，非估计）

| 门限 | 值 | 依据 |
| --- | --- | --- |
| 色度深度 | ≥ 0.006 | 8-bit 量化 + JPEG 噪声约 1.5/255 |
| 谱峰/中位数 | ≥ 8 | 色度通道噪声低 |
| 解释比例（自动检测） | ≥ 0.75 | 纯色带 0.93，现场照片 0.81，随机彩色场景均值 0.58 |
| 解释比例（外部给周期） | ≥ 0.35 | 纯色带 0.89–0.92，干净场景 0.00–0.02 |
| 三条带相位一致 | ≥ 0.75 | 闪烁覆盖全幅，场景色不会 |
| 亮度兜底（长周期） | 解释 ≥ 0.5 | 场景结构是宽带的，标准更严 |

## 实测

```
合成色度横带 200 例：检出 200/200，周期全对，残差 < 35%
960×720  周期 190：色度移除 96%
1600×1200 周期 391：色度移除 92%
960×720  周期 90 ：色度移除 99%
干净场景（文字行）+ 外部给 391 周期：拒绝
自动检测 + 文字行 127：127 px 波纹 0.002
```

单元测试 45 个（`ChromaBandingRepairTest`、`ArgbPlanesTest`）。

## 已知局限

- 只用合成图和截图验证，**尚未在真机、真实照片上确认**
- 长周期色度横带与场景的缓慢颜色变化在单张图上本就接近；刻意构造的平滑彩色场景仍有约 12% 会被判为候选（`repair` 自动路径）
- 修复是用户手动触发、只生成预览副本、不覆盖原图，误判代价可控

## 接线

```kotlin
val pixels = IntArray(w * h)
bitmap.getPixels(pixels, 0, w, 0, 0, w, h)
val outcome = ChromaBandingRepair.repairWithPeriod(
    ArgbPlanes.toPlanes(pixels), w, h, detectedPeriodRows, strength, BandingAxis.HORIZONTAL,
)
if (outcome.applied) {
    val fixed = ArgbPlanes.fromPlanes(outcome.planes!!, pixels)
    Bitmap.createBitmap(fixed, w, h, bitmap.config ?: Bitmap.Config.ARGB_8888)
}
```
