# A：横纹检测开发记录

依据本地 `../Project Plan.docx`，A 负责横纹检测，B 负责像素修复，C 负责 Android 核心，D 负责界面交互。第一版要求 Kotlin、本机离线运行。

## 第一步：逐行亮度统计

调用 `rowLuminance(image: Bitmap): DoubleArray`，每个输出值对应输入 Bitmap 的一行，范围为 0～255。使用 `0.299R + 0.587G + 0.114B` 近似亮度，再对该行全部像素取平均；不覆盖图片。

这是检测算法的输入，尚不能据此判断照片是否存在 LED 时序横纹。自然阴影、文字行、建筑结构也会造成行亮度变化。

输入约定：方向已经处理正确、可读取像素的软件 Bitmap、不透明像素。透明图片应先确定背景合成规则。本阶段不自动缩放；行坐标只对应传入图片，缩略图与原图的映射须在后续接口中明确。额外空间为一行像素及每行一个统计值，耗时像素运算由调用方放到后台线程。

## 第二步：周期性检测基线（2026-11-21）

已新增 `detectBanding(image: Bitmap, config: DetectionConfig): BandingResult`，默认参数可省略。实现为纯 Kotlin 数值分析加 Android Bitmap 读取适配，没有新增依赖，也没有修改 C/D 的界面或调度代码。

流程：四个等宽或近似等宽的纵向区域 → 每区逐行亮度 → 按区域宽度加权的整图序列 → 滑动局部直线拟合去趋势 → 归一化自相关的周期峰及半周期明暗反转检查 → 各区的周期与同相一致性检查 → 输出疑似状态和诊断信息。

已提供 `model/BandingResult` 接口草案、参数说明及调用样例，详见 [检测接口](detection-interface.md)。这是供 B/C 讨论的草案，尚未代表团队已确认这些字段。
