# 白色/灰色画面的宽幅色带检测

2026-11-23，feature/detection。

用户确认 04.jpg、05.jpg 的原画面为白色，照片中的颜色变化来自拍摄结果。因此新增独立的宽幅颜色变化检测，不要求至少两次完整周期。该判断不推断 LED、投影色序或其他具体硬件原因。

## API 和使用

`detectBanding(bitmap, assumeNeutralBackground = true)` 开启新模式，版本为 row-color-broad-v5。默认 false，保持原周期检测 v4 行为，避免把正常彩色内容的渐变一律归为拍摄伪影。

App 增加“原画面应为白色或灰色（检测宽幅色带）”复选框，默认关闭，支持保存该选择状态。勾选或取消会重新读取、检测所选照片，清除旧结果和修复预览。新结果显示“疑似宽幅色带”，没有虚构周期或概率。此模式下若发现宽幅候选，修复按钮明确提示暂不支持宽幅颜色修复。

新增 BandingStatus.SUSPECTED_BROAD_COLOR_BAND、BandingResult.broadColorEvidence，isSuspected 包含该状态。亮度和周期字段仍保留原含义；宽幅证据独立存储 channel、chromaSpread、regionSupport、validBinFraction。若已有周期候选，保留周期状态，同时附加宽幅证据。

## 规则

- 采样画面中央 80% 的宽度，分为四列区域；全高划分为 32 个横向分箱。没有实现投影幕布四边形自动定位。
- 忽略透明、过暗或极高饱和像素，减少黑字、人物和深色边框的影响。每个区域/分箱保留足量明亮背景像素后，使用颜色差值的中位数。
- 使用归一化色差 255×(R−G)/(R+G+B) 与 255×(B−G)/(R+G+B)，避免仅因共同明暗变化得到颜色变化。
- 至少三个区域有有效数据才形成逐箱共识，至少 16 个分箱有效；三箱平滑后用第 90 与第 10 百分位差衡量宽幅变化。
- 共识色差跨度至少 12；区域色差跨度至少 8，且与共识相关至少 0.75，至少四区中三区支持才输出候选。均为尚待更多数据标定的工程参数。

## 边界

中性原画面的确认是必要前提。真实彩色渐变背景也可能满足统计规则，不能自动判为成像伪影。本版不包含真实幕布定位、透视校正、自动确认白色内容、宽幅颜色修复或硬件成因分类。局部遮挡、光照颜色变化及背景不足仍可能影响结论。
