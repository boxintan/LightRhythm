# 13 号百叶窗误检修正

2026-11-26，`feature/detection-refinement`，基于 `1233936`。

## 问题与原因

用户确认 13.jpg 为正常百叶窗照片。旧版在 960×1280、720×960、360×480 三种尺寸均输出 `SUSPECTED_LOCAL_BANDING`，分别有 5、7、9 个局部位置。照片中叶片的透视变化形成重复明暗结构；跨位置周期相近并不足以说明存在拍摄异常。

原有聚类只要求四个候选覆盖至少两列、两行，并与锚点的周期和倾斜相近。这允许某一列的上方纹理与另一列的下方纹理拼成证据，也会在按倾斜过滤时丢掉同列中的矛盾信息。

## 修改

1. 先收集与锚点周期相容的所有位置，再按倾斜选取候选簇。周期相容仍为锚点的 20%（至少容许 1 行），原有幅度、自相关、半周期反转、子区支持及最小周期规则保留。
2. 对上述周期相容位置，找出有两个或更多不同纵向位置的列。同一列的各位置须保持周期差不超过较短周期的 20%（至少 1 行），倾斜差不超过一次搜索步长 0.05。
3. 持续一致的列占重复出现列的比例，至少达到 `DetectionConfig.minRegionSupport`（默认 0.75）；最终候选簇中至少有两列各自得到两个纵向位置的支持。不能先删除倾斜不合的行，再计算这个比例。
4. 倾斜选择改为最大化 `残差 RMS × 周期相关`。只看归一化相关，会让小窗口中幅度很弱、相关略高的混叠方向胜出；结合保留下来的周期幅度后，小尺寸平行条纹的倾斜估计更稳定。

这是对局部证据一致性的保守约束，没有识别“窗户”物体，也没有按文件名或图片内容哈希设例外。128/64 两种窗口仍独立判定，不合并尺度票数。

公开函数与结果字段保持不变，像素入口版本为 `row-local-periodicity-v8`，中性背景模式为 `row-local-broad-v8`；整行轮廓入口和摩尔纹算法未更改。未通过局部判据时保留原有整行检测结果，不将其解释为照片已被证明正常。

## 验证

- 新增三项 JVM 测试：透视收敛叶片、平滑收敛条纹、不同倾斜的平行条纹。前两项在旧实现上失败，在本实现通过；平行条纹保持可检出。既有小屏幕、文字、孤立纹理、幅度/周期配置回归全部通过。
- 桌面算法/工具测试 87 项通过；完整 App JVM 109 项通过，无失败、无跳过。范围重叠，不相加为独立覆盖数量。
- debug APK、Android 测试 APK 和 `lintDebug` 通过；使用独立 `.detectiontest` 包。
- API 37 / Android 17 无窗口模拟器 40 项设备测试全部通过，`OK (40 tests)`，无失败、无跳过。新增设备测试确认 13 在 Android ImageDecoder 的 1280/960/480 三种最长边下不触发横纹和摩尔纹，Bitmap 与源文件不变；新增页面测试确认导入 13 后无横纹警报、点击修复不生成结果。09、颜色条带/摩尔纹、导入保存及旋转回归保持通过。

复现构建沿用 `--offline -PdetectionVerification=true :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug --no-configuration-cache`。照片通过 instrumentation 参数 `detectionSampleDirectory` 在本机提供，新增检查位于 `DetectionTileScaleTest` 和 `LocalBandingPhotoTest`，不会将照片打包进 APK。

本地证据位于忽略的 `build/blinds-review`：`before.csv`、`new-samples-before.csv`、`after-consistency.csv`、`legacy-regression.txt`、`device-tests.txt`。诊断照片、原图、CSV 和构建产物均不提交。

## 边界

本轮修正的是 13 及相似的透视不一致误检，并非通用百叶窗/栅栏识别。平行、等间距的真实纹理仍可能与周期频闪具有相同统计特征；弯曲明显或只覆盖很小区域的真实条带也可能因保守约束而漏检。需要更多有标签的困难负样本和独立验证集，不能宣称所有窗户误检均已解决。
